# 民商事案件工作管理平台

## 总原则

维护一个案件主数据文件作为唯一事实源。每次收到新信息先入库、校验、标注来源和置信状态，再更新对外成果。不得用推测填补日期、送达、催告、付款、签署或法院程序事实。

法律文书、金额、期限、法条和案例引用均须律师人工复核后方可提交、发送或公开。

## 首次运行

1. 先运行 `scripts/create_case_workspace.py`，为每案建立一个总工作区，顶层严格保留以下五个文件夹：`①当事人提供材料、②诉讼文件、③立案文件、④流程性文件、⑤归档文件`。
2. 递归读取案件文件夹并建立文件清单，不改变原始材料。
2. 阅读 `references/case-schema.md`，创建或更新 `case_master.json`。
3. 阅读 `references/stage-machine.md`，识别当前案件阶段和下一触发事件。
4. 阅读 `references/output-matrix.md`，仅生成当前阶段需要的三端成果。
6. 建立 `validation_log.md`，记录矛盾、缺口、假设禁区和人工确认事项。

## 五文件夹案件工作区

- `①当事人提供材料`：保存委托人原始提交的 DOCX、XLSX、PDF、JPG、PNG、聊天记录、合同和初步证据。保持原文件不变，不把工作流生成稿放入此处。
- `②诉讼文件`：保存律师与 Codex 共同形成的可编辑 DOCX、XLSX、PPTX，包括委托合同、授权委托书、起诉状、证据目录、案例分析、客户可视化材料和案例检索报告。工作稿、定稿须在文件名中区分。
- `③立案文件`：只保存经当事人签字或律师事务所盖章、可实际提交法院的 PDF。未签章初稿不得进入本目录。
- `④流程性文件`：保存法院、仲裁机构及办案机关发送的传票、保全裁定、保全回执、受理通知、举证通知、缴费通知、送达凭证等。同步维护 `程序文件登记与期限提醒.json`。
- `⑤归档文件`：保存依据归档模板生成的封面、目录、缺失必备材料清单和全卷 PDF 合集。原始材料不因归档而删除或移动。

每份新材料只进入一个主目录；需要在其他阶段使用时建立索引或副本并记录来源，不静默移动原件。

## 平台三阶段

### 诉前准备

1. 优先读取用户上传的 DOCX、XLSX、PDF、JPG、PNG 等材料，能够从材料取得的信息不得要求用户重复填写。
2. 通过对话只追问会影响管辖、时效、请求、证据或风险判断的缺口，并说明提问原因；保留律师手动补充内容且标记为独立来源。
3. 生成初步案情分析和现行法律规定检索报告。
4. 根据具体案件生成接案笔录问题清单和关键证据索取清单，逐项写明必要性、提供人、取得方式和替代证据。
5. 为客户生成可视化 PPT、诉讼流程图和视频脚本/分镜，展示重要节点、争议焦点、证据任务、诉讼策略和风险。

### 诉讼程序

1. 生成代理意见、民事起诉状、证据目录和案例检索报告的可编辑初稿。
2. 用户修改初稿后，理解其修改意图并润色；不得改变已核验事实、金额、诉讼立场和引用来源。
3. 对案例检索报告调用可用的元典、北大法宝等工具，记录检索式、筛选过程和可追溯来源。
4. 持续接收法院文书、12368短信、答辩、证据、开庭和调解信息，更新期限、争点、质证和庭审任务。

### 结案归档

1. 读取全案文书，识别文件类型、日期、版本和程序阶段；先输出拟归档映射、重复项、缺失项和命名建议，经律师确认后再移动或重命名文件。
2. 按规律化目录归档并形成归档索引。
3. 归档完成后生成全案复盘 PPT，覆盖案件特点、事实时间轴、诉讼策略、争议焦点、证据组织、适用法律、结果和规律总结。
4. 结合上述内容生成微信公众号可直接使用的排版稿；严格脱敏、保护客户秘密并注明裁判生效状态。

## 每次新增材料

1. 记录来源文件、接收时间、文书制作日、实际送达日及提取方式。
2. 比对案件主数据，不静默覆盖旧事实；发生冲突时保留旧值和新值并标记待确认。
3. 判断触发器：新证据、法院通知、答辩、开庭、裁判、执行或结案。
4. 只更新受影响的主数据、期限、证据矩阵和成果，避免整套文件无差别重做。
5. 对新期限输出“触发事实—起算规则—计算过程—截止日—来源—人工校正”链条。

## 三端输出

### 面向委托人

使用易懂但审慎的表达，结论先行。生成案件分析、风险分级、可视化流程、客户待办证据清单、费用和进展说明、微信沟通简版。不得承诺胜诉或回款。

### 面向法官

围绕争议焦点组织法条、案例和证据。优先使用已配置的北大法宝、元典或其他权威法律检索 MCP；记录检索式、筛选标准、案号、法院、裁判日期、裁判要旨、相似点、差异点和可引用性。无法调用数据库时明确说明，不编造案例或法条。

生成类案检索报告、法条总结、诉讼观点报告、证据目录、质证意见、代理词或庭审提纲。区分现行法与行为发生时法律，区分指导性案例、典型案例、一般类案和仅供线索材料。

### 面向律师本人

维护案件驾驶舱、事实时间轴、金额底稿、证据矩阵、程序期限、风险校验、补证清单和庭前倒排看板。收到裁判后进入上诉/执行评估；案件终结后生成归档清单、结案报告、经验复盘及脱敏微信推文。

## 阶段触发规则

- 收到12368短信或法院文书：先提取实际送达日，再计算期限；无法确认送达日时只登记不计算。
- ④流程性文件中出现可确定的法定或法院指定期限后，创建一次性自动化提醒，提醒时间为截止日前一日09:00；同时在提醒正文写明案件名称、文书名称、送达日、期限规则、截止日、来源文件及“律师人工复核”。同一事项存在法院明确日期时以法院文书为准；无法确认实际送达日时不得创建截止日提醒。
- 收到被告答辩或证据：生成逐项质证意见、反驳证据需求并更新争点。
- 收到开庭传票：生成倒排计划、客户庭前核对、庭审提纲和原件清单。
- 收到裁判文书：提取送达日、裁判结果、履行期限；生成上诉评估或执行方案。
- 发生调解：核验本金、费用、付款节奏、担保、加速到期、违约和司法确认条款。
- 案件终结：按 `references/archive-rules.md` 归档，再生成内部复盘和对外脱敏内容。

## 硬性校验

- 金额必须有公式或逐项计算，核对诉请、法院系统标的额和诉讼费口径。
- 未知日期保持 `null` 或“待确认”，可记录相对先后顺序。
- 期限以实际送达、法定规则和法院文书三者为依据；节假日顺延需人工核验。
- 案例引用必须可追溯到检索结果，不以模型记忆代替检索。
- 对外文件不得暴露内部风险标签、客户隐私或与案件无关的模板残留。
- 微信推文必须脱敏，裁判未生效或事实存在争议时使用审慎表述。

## 文件工具

创建 DOCX、PDF、XLSX 时调用相应文档技能并完成渲染检查。需要生成委托手续、起诉材料等标准诉讼文件时调用 `litigation-docs-generator`。快速法律分析可结合 `wulilaw-legal-consulting`，但案件主数据仍以本 Skill 为准。

## 结束本轮

输出本轮新增或更新成果、尚未解决的高风险事项、下一自动触发条件。若没有外部新增信息，保持监控状态，不重复生成同一成果。
