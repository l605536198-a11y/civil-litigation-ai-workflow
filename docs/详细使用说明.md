# 民商事案件工作管理平台：零基础详细使用说明

> 适用对象：中国大陆民商事诉讼律师、律师助理及法律科技实践者。  
> 核心原则：AI负责整理、生成和提醒，律师对事实、法律、期限、金额及最终交付承担复核责任。

## 1. 一分钟理解这个工作流

这个 Skill 把民商事案件分成三个阶段：

1. **诉前准备**：读取材料，完成初步分析、法律检索、接案问题、证据清单、客户流程图和沟通PPT。
2. **诉讼程序**：生成并润色起诉状、代理意见、证据目录、案例检索报告；登记法院文书并管理期限。
3. **结案归档**：生成归档映射、缺失材料清单、封面目录和PDF合集，并生成复盘PPT与脱敏微信推文。

它服务三类读者：委托人需要看得懂，法官需要可核验，律师需要可追踪、可复盘。

## 2. 交付包里有什么

```text
参赛交付包_民商事案件工作管理平台/
├─ skill/        可安装的 Skill
├─ web/          参赛版网页及本地服务
├─ templates/    委托手续、诉讼文书、归档和内容模板
├─ samples/      已脱敏的演示案件
├─ manifest.json
├─ 详细使用说明.md
├─ 参赛项目说明.md
└─ 启动参赛版平台.cmd
```

## 3. 安装 Skill

### Codex 桌面版

把 `skill/civil-commercial-litigation-workflow` 整个文件夹复制到：

```text
C:\Users\你的用户名\.codex\skills\
```

重启 Codex，输入：

```text
请使用 $civil-commercial-litigation-workflow 建立一个新案件工作区。
```

能够识别 Skill 名称即安装成功。

### 其他支持 Skill 的桌面 Agent

在设置中寻找“Skills”“规则包”“项目指令”或“导入技能”，选择整个 Skill 文件夹。不要只上传模板；`SKILL.md`、`references` 和 `scripts` 应保持原目录关系。

### 只支持系统提示词的 Agent

1. 新建案件项目；
2. 将 `SKILL.md` 设置为项目规则或系统提示词；
3. 上传当前任务需要的 `references` 文件；
4. 能运行脚本时使用 `scripts/create_case_workspace.py` 建立案件目录；不能运行脚本时，让 Agent 按下述五文件夹结构建立。

这类平台仍可使用核心工作方法，但自动建目录、网页回填和定时提醒能力可能受限。

## 4. 启动网页平台

Windows用户：

1. 安装 Node.js 18或更高版本；
2. 安装并登录支持命令行调用的桌面 Agent；
3. 如 Codex 命令不在系统 PATH，在环境变量 `CODEX_EXE` 中填写其完整路径；
4. 双击 `启动参赛版平台.cmd`；
5. 浏览器访问 `http://127.0.0.1:8787/`。

不要直接双击 `web/index.html`，否则上传和自动生成接口无法使用。网页是统一入口，实际推理和文件生成仍由本地 Agent 完成。

## 5. 每个案件的固定目录

```text
案件名称/
├─ ①当事人提供材料
├─ ②诉讼文件
├─ ③立案文件
├─ ④流程性文件
└─ ⑤归档文件
```

- `①当事人提供材料`：客户原始文件，只读保留，不覆盖、不改名。
- `②诉讼文件`：律师与AI共同形成的DOCX、XLSX、PPTX等可编辑工作稿。
- `③立案文件`：签字或盖章后，可以实际提交法院的PDF。
- `④流程性文件`：受理通知、传票、举证通知、保全裁定、送达凭证等。
- `⑤归档文件`：封面、目录、缺失清单和归档PDF合集。

## 6. 第一次运行怎么说

```text
请使用“民商事案件工作管理平台”处理本案。
当前阶段：诉前准备。
目标：评估是否起诉以及需要补充哪些证据。
我已上传合同、付款记录、聊天记录和主体证明。
请先读取材料，能够从文件取得的信息不要重复问我；
只追问会影响管辖、时效、诉请、证据或风险判断的缺口。
```

工作流应先创建 `case_master.json` 和 `validation_log.md`。前者保存已确认事实，后者记录冲突、缺口和人工核验事项。

## 7. 三个阶段怎么操作

### 诉前准备

先上传材料，再生成初步案件分析。检查输出是否包含：法律关系、案由、管辖、时效、金额公式、争议焦点、证据矩阵、风险和下一步行动。

确认基础事实后，再生成客户PPT、流程图或视频脚本。对客户的表达应易懂，但不得承诺胜诉或回款。

### 诉讼程序

把法院文书放入 `④流程性文件`，输入：

```text
请读取新增法院文书，提取文书制作日、实际送达日、期限规则和截止日。
无法确认实际送达日时，不要推算截止日，只列入待律师核验事项。
```

生成起诉状、代理意见、证据目录或案例检索报告时，优先使用 `templates` 对应模板。律师修改后可要求：

```text
理解我的修改意图并润色最新版本。
不得改变已核验事实、金额、诉讼立场和引用来源；
发现冲突时只提示，不要自行补写。
```

### 结案归档

先生成“拟归档映射”，核对重复文件、版本和缺失材料。只有律师确认后，才允许移动或重命名文件并生成PDF合集。

微信推文及公开材料必须脱敏，包括当事人名称、身份号码、地址、联系方式、合同编号、金额、案号以及能够反向识别客户的信息。

## 8. 法律数据库与MCP

推荐连接元典、北大法宝或律所批准的法律数据库。必须满足：

1. 工具返回可追溯的法条或案例来源；
2. 报告记录检索式、筛选条件、案号、法院、裁判日期和相似性；
3. 数据库不可用时明确写“未完成权威数据库检索”；
4. 禁止以模型记忆替代真实案例检索。

没有MCP时，工作流仍可整理材料和生成文书结构，但案例表格不能用虚构内容填满。

## 9. 如何修改输出格式

`templates` 是格式控制层。修改模板后，下一次生成应采用新的栏目、措辞和版式。

- DOCX：保留占位符和签署栏，可调整字体、页边距、表格和标题样式。
- PPTX：可调整母版、配色、字体、页脚和占位区。
- Markdown：可调整栏目和微信公众号排版结构。
- 模板变化后重新生成新版本，不要静默覆盖律师定稿。

## 10. Token用量和成本控制

用量取决于材料长度、OCR页数、检索轮次和输出数量。建议：

- 先提取事实，再做法律检索，最后生成文书；
- 案件主数据没有变化时，不重写无关文件；
- 长PDF先OCR并建立分页索引；
- 一次只生成当前阶段需要的成果；
- 案例检索先确定争点，再限定检索范围。

网页首页所示Token为估算区间，不是价格承诺；应以实际Agent的用量面板为准。

## 11. 提交、发送或公开前的复核清单

- [ ] 当事人信息和代理权限准确；
- [ ] 诉讼请求和金额计算一致；
- [ ] 管辖、时效、送达日及截止日经过人工复核；
- [ ] 法条为适用时点的有效规范；
- [ ] 案例名称、案号和裁判要旨可以追溯；
- [ ] 证据页码、原件状态和证明目的准确；
- [ ] 对外材料没有客户秘密或模板残留；
- [ ] 公开内容已脱敏并注明裁判是否生效；
- [ ] AI生成文件已经由承办律师最终审阅。

## 12. 常见故障

### 网页显示“本地服务未启动”

通过启动脚本打开，不要直接双击HTML；检查Node.js、8787端口、Agent CLI及 `CODEX_EXE` 配置。

### Agent重复询问材料中已有的信息

要求它“先递归读取原始材料，能够从材料取得的信息不得重复提问”，并检查文件是否进入当前案件目录。

### 案例检索报告都是“待确认”

通常是法律数据库MCP没有连接或未返回可追溯结果。检查连接后重新检索；禁止要求模型编造案例填表。

### 能否让AI直接提交法院

不能。平台生成的是工作稿或辅助材料。签字、盖章、提交、发送、期限确认和诉讼决策必须由律师完成。

## 13. 跨平台迁移检查表

- [ ] 目标Agent能加载项目规则或Skill；
- [ ] `SKILL.md`和引用路径保持有效；
- [ ] Python脚本可运行，或已有替代文件工具；
- [ ] DOCX、PDF、PPTX生成工具可用；
- [ ] 法律数据库MCP已连接并授权；
- [ ] 文件存储符合律所数据安全要求；
- [ ] 已用脱敏示例完成一次全流程测试；
- [ ] 已确认目标Agent不会把案件材料发送到未经授权的服务。

完成以上检查后，即可把同一套方法复用到新案件和不同桌面 Agent。
