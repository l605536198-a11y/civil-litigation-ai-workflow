# 民商事案件工作管理平台：工作流详细说明

> 版本：参赛正式版 v2.2  
> 适用对象：中国大陆民商事诉讼律师、律师助理、律所知识管理人员及法律科技实践者。  
> 使用边界：本平台用于辅助信息整理、法律研究、文书起草、流程管理和归档复盘，不替代承办律师的专业判断。事实、金额、期限、法律依据、案例引用及对外文件必须由律师人工复核。

## 一、平台是什么

“民商事案件工作管理平台”是一套可移植的法律 AI Skill，将案件办理拆分为“诉前准备—诉讼程序—结案归档”三个阶段，并围绕同一份案件主数据持续更新成果。

### 1. 参赛定位

- **项目名称**：民商事案件工作管理平台
- **申报方向**：流程搭建
- **项目摘要**：以真实办案流程为基础，通过对话或上传 DOCX、XLSX、PDF、JPG、PNG 等材料建立案件唯一事实源，按委托人、法官和承办律师三类读者生成差异化成果，并持续维护证据、期限、版本和归档链条。

### 2. 核心创新

1. 以案件主数据作为唯一事实源，降低多轮对话中的事实漂移；
2. 采用“三阶段、三端输出”，让同一案件事实服务不同阅读对象；
3. 固定五文件夹工作区，区分原始材料、可编辑工作稿、法院提交件、流程文书和归档卷宗；
4. 将模板设为格式控制层，律师可以通过调整模板控制后续输出；
5. 将程序期限拆解为“触发事实—实际送达日—起算规则—计算过程—截止日—人工复核”；
6. 法条和案例必须来自可追溯检索结果，数据库不可用时明确保持待检索；
7. 同时提供桌面 Agent 对话入口和本地网页入口，减少重复复制提示词。

### 3. 对应评审维度

| 评审维度 | 项目对应能力 |
|---|---|
| 法律专业价值（30%） | 覆盖接案、证据、文书、检索、期限、庭审准备和归档等实务环节 |
| 实操与易用（25%） | 提供网页入口、统一说明、固定目录、模板和脱敏示例 |
| 推广价值（20%） | 核心 Skill 不绑定单一模型，可迁移至支持 Skill 或项目规则的桌面 Agent |
| 合规与安全（25%） | 关键事实不猜测、案例可追溯、材料本地管理、公开成果脱敏、律师最终复核 |

### 4. 建议参赛演示路径

使用交付包中的脱敏示例案件，依次演示：上传材料 → 初步分析与证据清单 → 起诉状与案例检索报告 → 新增法院文书与期限更新 → 归档 PDF 合集、案件复盘和脱敏微信推文。

平台有两种使用入口：

1. **桌面 Agent 对话入口**：安装 Skill 后，在 Codex 或其他支持项目规则、Skill、工具调用的桌面 Agent 中直接上传材料并下达任务。
2. **本地网页入口**：在安装桌面 Agent 和本地服务后，通过网页上传材料、选择任务、预览和下载成果。网页是操作界面，实际推理和文件生成仍由本机 Agent 与 Skill 完成。

公开部署在 GitHub Pages 的网页属于静态体验版，只展示界面和工作方法；完整的上传、分析和文件生成功能需要在本机启动后端。

## 三、使用前必要配置

### 1. 最低配置

| 项目 | 最低要求 | 用途 |
|---|---|---|
| 操作系统 | Windows 10/11；其他系统可手动启动 | 保存案件文件并运行本地网页 |
| 桌面 Agent | 能读取本地文件并加载项目规则或 Skill | 理解案件、调用工具、生成成果 |
| 模型 | 支持中文长文本与工具调用的模型 | 案情分析和文书生成 |
| Node.js | 18 或更高版本 | 运行网页本地服务 |
| Python | 3.10 或更高版本，建议安装 | 建立案件目录、期限登记等脚本 |
| 浏览器 | Chrome、Edge 等现代浏览器 | 使用网页入口 |
| 文件权限 | 对案件工作区具有读写权限 | 保存主数据与输出文件 |

只使用桌面 Agent 对话入口时，Node.js 和网页服务不是必需项；需要网页完整功能时必须配置 Node.js 和可被本地服务调用的 Agent CLI。

### 2. 推荐配置

- 支持 DOCX、XLSX、PDF、PPTX 创建和读取的文档工具；
- OCR 工具，用于扫描 PDF、聊天截图和照片；
- 元典、北大法宝或律所授权法律数据库 MCP；
- 支持定时任务或日历写入的工具，用于诉讼期限提醒；
- 独立的加密磁盘、律所文件服务器或合规私有存储；
- Git，用于管理 Skill 与模板版本，但不得把真实案件材料提交到公开仓库。

### 3. 必须确认的安全设置

- 明确 Agent、模型、MCP 和云盘是否会保存、训练或转发输入数据；
- 真实身份证号、地址、联系方式、商业秘密等仅进入律所批准的环境；
- 公开演示、比赛提交和微信公众号内容必须使用脱敏材料；
- 对外发送、法院提交、文件移动、批量重命名和归档合并前由律师确认；
- 不把模型推测写入已确认事实，不用模型记忆虚构法条或案例。

## 四、建议使用的工具

### 1. 必要工具

- **桌面 Agent**：负责读取文件、执行 Skill、调用脚本并生成成果。
- **本地文件系统**：保存案件原件、工作稿、法院文件和归档成果。
- **Word/PDF/PPT 工具**：打开和人工复核可编辑文书及展示材料。

### 2. 法律检索工具

优先连接元典、北大法宝等能够返回可追溯来源的法律数据库。案例检索报告至少记录：检索问题、检索式、筛选标准、案号、法院、裁判日期、裁判要旨、相似点、差异点和可引用性。

数据库不可用时，平台可以生成检索方案和报告框架，但应明确标注“未完成权威数据库检索”，不得用虚构案例填表。

### 3. 文档与可视化工具

- DOCX：用于起诉状、代理意见、接案笔录和案例检索报告；
- XLSX：用于证据矩阵、金额计算底稿和期限清单；
- PDF：用于法院提交版、流程性文件和全卷归档合集；
- PPTX：用于客户案件分析、流程可视化和全案复盘；
- OCR：用于识别扫描合同、回单、微信截图和法院纸质文书。

### 4. 提醒工具

可以使用 Agent 自带自动化、系统日历、Todoist、TickTick 或律所案件系统。提醒正文应包含案件名称、文书名称、实际送达日、期限规则、计算过程、截止日、来源文件和“律师人工复核”提示。

## 五、具体功能

### 1. 诉前准备

- 读取 DOCX、XLSX、PDF、JPG、PNG 等案件材料；
- 自动提取当事人、事实、日期、金额、合同履行和争议经过；
- 生成案件主数据、事实时间轴、争议焦点和初步法律分析；
- 检索相关法条、司法解释和可追溯案例；
- 生成接案笔录问题清单，解释每个问题对管辖、时效、诉请或证据的影响；
- 生成关键证据索取清单，列明必要性、持有人、取得方式和替代证据；
- 生成客户版流程图、案件分析 PPT 和视频脚本/分镜；
- 保留律师手动补充窗口，并记录信息来源。

### 2. 诉讼程序

- 生成和润色民事起诉状、代理意见、证据目录和案例检索报告；
- 根据律师修改理解润色意图，但不改变核验事实、诉讼立场和引用来源；
- 接收答辩状及对方证据，更新争议焦点并形成质证思路；
- 接收受理通知、举证通知、传票、保全裁定、缴费通知等流程文件；
- 提取实际送达日、期限规则和截止日，生成期限登记及提醒；
- 收到开庭通知后生成庭前倒排计划、原件清单和庭审提纲；
- 收到调解方案后核验本金、费用、履行节奏、担保及违约条款。

### 3. 结案归档

- 识别案件文件的类型、日期、版本和程序阶段；
- 先生成拟归档映射、重复项和命名建议，确认后再整理；
- 对照归档目录列出带 `*` 的必归档材料缺失项；
- 生成卷宗封面、编制目录和包含现有文件的 PDF 合集；
- 生成全案复盘 PPT，归纳案件特点、策略、争点、证据和适用法律；
- 生成经脱敏、适合微信公众号排版的案件总结推文；
- 收到裁判后辅助进行上诉或执行评估。

### 4. 三类交付对象

| 对象 | 主要成果 | 表达要求 |
|---|---|---|
| 委托人 | 案件分析、流程图、证据待办、客户 PPT | 易懂、审慎，不承诺结果 |
| 法官 | 起诉状、代理意见、证据目录、类案及法条报告 | 围绕争点，可核验、可追溯 |
| 律师 | 主数据、金额底稿、期限、证据矩阵、归档和复盘 | 可追踪、可校验、可复用 |

## 六、每案固定工作区

```text
案件名称/
├─ ①当事人提供材料
├─ ②诉讼文件
├─ ③立案文件
├─ ④流程性文件
└─ ⑤归档文件
```

- `①当事人提供材料`：保存客户提交的原始文件，原则上不修改、不覆盖；
- `②诉讼文件`：保存律师与 Agent 共同形成的 DOCX、XLSX、PPTX 工作稿和定稿；
- `③立案文件`：只保存已签字或盖章、可以向法院提交的 PDF；
- `④流程性文件`：保存法院文书、12368 短信、传票、保全材料和送达凭证；
- `⑤归档文件`：保存封面、目录、缺失清单和全卷 PDF 合集。

每份材料只设一个主存放位置；需要跨阶段引用时建立索引或有来源记录的副本，不静默移动原件。

## 七、桌面 Agent 直接运行流程

### 第一步：安装 Skill

将整个 `skill/civil-commercial-litigation-workflow` 文件夹导入目标 Agent。必须保持 `SKILL.md`、`references` 和 `scripts` 的相对目录关系。

### 第二步：创建案件工作区

示例指令：

```text
请使用 $civil-commercial-litigation-workflow 为本案创建五文件夹案件工作区。
当前阶段为诉前准备。先读取我上传的材料，建立 case_master.json 和 validation_log.md。
能够从文件取得的信息不要重复询问，只追问影响管辖、时效、诉请、证据或风险判断的缺口。
```

### 第三步：上传原始材料

将合同、付款凭证、聊天记录、主体证明、催告材料等放入 `①当事人提供材料`。扫描件先 OCR；模糊页、缺页和无法识别内容应标注待核验。

### 第四步：确认案件主数据

检查当事人、法律关系、关键日期、金额、管辖连接点、诉讼请求和证据来源。未知日期保留为空或“待确认”，只知道先后顺序时仅记录相对顺序。

### 第五步：按阶段生成成果

诉前先生成案情分析、问题清单和证据清单；事实确认后再生成客户 PPT。诉讼中按需生成文书并接收法院文件。结案时先核对归档映射，再生成 PDF 合集和复盘材料。

### 第六步：律师复核并定稿

重点复核事实、金额公式、管辖、时效、实际送达日、截止日、适用法时点、案例来源、证据页码和脱敏状态。工作稿经签字或盖章后，才复制 PDF 到 `③立案文件`。

## 八、本地网页运行流程

### 1. Windows 快速启动

1. 安装 Node.js 18 或更高版本；
2. 安装、登录桌面 Agent，并确保其命令行工具可以运行；
3. 如果系统找不到 Codex 命令，将 `CODEX_EXE` 环境变量设为 Agent CLI 的完整路径；
4. 双击 `启动参赛版平台.cmd`；
5. 浏览器访问 `http://127.0.0.1:8787/`；
6. 在网页中选择案件阶段、上传材料并启动对应任务；
7. 在网页预览结果，下载文件后由律师复核。

不要直接双击 `web/index.html` 期待完整功能；静态 HTML 无法自行调用本机 Agent 和文件生成接口。

### 2. macOS/Linux 手动启动

进入交付包目录，确认 `node` 与 Agent CLI 可用，然后运行：

```bash
node web/server.js
```

再访问 `http://127.0.0.1:8787/`。Windows 启动脚本不可直接用于 macOS/Linux，但网页和核心 Skill 方法可以迁移。

## 九、跨不同 Agent 软件的安装说明

不同产品对“Skill”的叫法和能力不同，应按以下三档迁移。

### A. 原生支持文件型 Skill 的 Agent

适用于能够识别 `SKILL.md` 并访问其子目录的 Agent，例如已配置 Skill 机制的 Codex：

1. 复制 `civil-commercial-litigation-workflow` 整个目录到该 Agent 的技能目录；
2. 重启或刷新技能列表；
3. 检查 Agent 是否能读取 `references/case-schema.md`；
4. 用脱敏示例运行一次；
5. 再接入法律检索 MCP 和真实案件工作区。

Codex Windows 常见安装位置：

```text
C:\Users\你的用户名\.codex\skills\civil-commercial-litigation-workflow\
```

调用示例：

```text
请使用 $civil-commercial-litigation-workflow 处理当前案件材料。
```

### B. 支持项目规则/知识库，但不原生识别 Skill 的 Agent

适用于支持 Projects、Workspace Instructions、Rules 或 Knowledge 的桌面 Agent：

1. 为每个案件建立独立项目；
2. 将 `SKILL.md` 全文设为项目规则；
3. 将 `references` 文件加入项目知识库；
4. 把 `templates` 作为可读取的模板目录；
5. 将案件五文件夹授权给 Agent；
6. 如果支持 MCP，连接法律数据库和文件工具；
7. 如果不能运行脚本，让 Agent 按固定目录和 JSON 字段人工建立主数据。

这类安装可以复用分析和生成逻辑，但自动建目录、期限任务和网页回填取决于 Agent 是否提供对应工具。

### C. 只支持聊天和附件上传的 Agent

1. 每个新对话先上传 `SKILL.md` 和当前阶段所需的 reference；
2. 上传案件材料和需要采用的模板；
3. 明确要求先输出结构化案件主表，再生成文书；
4. 由律师手动下载成果并放入五文件夹；
5. 期限提醒转入人工日历或案件系统。

这种模式不能保证跨会话持续记忆，也无法自动整理本地文件，适合体验和单次文书任务，不适合作为无人值守案件管理系统。

### D. MCP 安装与兼容原则

MCP 的配置文件位置、认证方式和工具名称由各 Agent 决定，不能直接照搬另一款软件的配置。迁移时逐项验证：

- Agent 是否支持 MCP 客户端；
- 法律数据库服务是否已安装、登录并取得授权；
- 工具能否返回正文、案号、法院和来源链接；
- 文件系统权限是否限定在当前案件目录；
- 失败时是否明确报告，而不是回退到模型猜测。

## 十、第一次完整运行示例

```text
请运行“民商事案件工作管理平台”。

案件阶段：诉前准备。
代理立场：原告。
任务目标：判断是否起诉并形成客户沟通材料。

请依次执行：
1. 递归读取①当事人提供材料，不修改原文件；
2. 建立案件主数据、事实时间轴和校验日志；
3. 只询问影响管辖、时效、诉请、证据或风险的缺失信息；
4. 生成初步案情分析、接案笔录问题清单和关键证据清单；
5. 使用已连接的权威法律数据库检索法条和类案，并保留检索轨迹；
6. 待我确认事实后，再生成客户版流程图和案件分析PPT；
7. 最后列出本轮新增成果、高风险待确认事项和下一步行动。
```

收到法院文书时：

```text
请读取④流程性文件中的新增文书，提取文书制作日和实际送达日。
按照“触发事实—起算规则—计算过程—截止日—来源—人工校正”登记期限。
实际送达日无法确认时不得推算截止日，也不得创建提醒。
```

## 十一、模板如何控制输出

`templates` 是工作流的格式控制层。律师可以通过替换或修改模板来控制栏目、固定措辞、字体、表格、页边距、配色、母版、页脚和签署栏。

- 修改 DOCX 模板时保留必要占位符和签署结构；
- 修改 PPTX 模板时统一母版、字体和品牌色；
- 修改 Markdown 模板时可调整微信公众号栏目及排版；
- 模板变更后生成新版本，不覆盖已经由律师确认的定稿；
- 模板内容与已核验事实冲突时，以案件主数据为准并提示人工确认。

## 十二、Token 用量与效率建议

Token 用量随材料页数、OCR 结果、检索轮次、上下文长度和成果数量变化，无法承诺固定值。应以所用 Agent 的实际计费或用量面板为准。

降低消耗的方法：

1. 先提取事实，再检索法律，最后生成文书；
2. 每次只处理新增材料和受影响的成果；
3. 长 PDF 先 OCR、分页并建立索引；
4. 先确定争议焦点，再限定案例检索式；
5. 将已确认事实写入案件主数据，避免反复发送全部历史材料；
6. 一个阶段确认后再进入下一阶段，减少无效重写。

## 十四、常见问题

### 1. 网页显示“本地服务未启动”

应通过启动脚本或 `node web/server.js` 打开；检查 Node.js、8787 端口、Agent CLI 和 `CODEX_EXE`。直接打开静态 HTML 不能使用后端功能。

### 2. Agent 重复询问材料中已有信息

要求其先递归读取原始材料并更新案件主数据，同时检查附件是否真正上传成功、扫描件是否已 OCR。

### 3. 案例检索报告大量显示“待确认”

通常是法律数据库没有连接、认证过期或没有返回可追溯结果。恢复 MCP 后重新检索；不能让模型编造案例补齐表格。

### 4. 是否可以让 AI 自动向法院提交

不可以。生成文书、签章、发送、提交、期限确认、诉讼策略和和解决定应由承办律师完成或明确授权的专业人员操作。

### 5. 其他人能否通过 GitHub 网页直接处理案件

公开 GitHub Pages 默认是静态体验版。要让他人在线上传材料并真实运行，需要另行部署安全后端、模型接口、账户权限、租户隔离、加密存储、日志审计和数据删除机制；不建议把真实案件材料交给未经安全评估的公共演示站点。
